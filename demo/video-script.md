## 🎯 演示节奏控制

5 分钟很紧凑，每个环节都要卡时间：

```
0:00 ──── 0:30 ──── 1:00 ──────── 2:30 ──── 3:30 ──── 4:30 ──── 5:00
 │  开场  │  Docker  │  AI 对话    │  RAG   │  JMeter  │  收尾   │
 │  30s   │  30s     │   90s       │  60s   │   60s    │  30s   │
```

**超时处理优先级**：
1. **可以删**：开场介绍再短一点，README 滚动删掉，直接进 Docker
2. **可以删**：Docker 启动直接跳过 ps 命令
3. **不能删**：AI 对话三个场景（核心卖点）
4. **不能删**：JMeter 结果展示（数据支撑）
5. **不能删**：结尾 Gitee 链接展示

## 📞 面试现场 Q&A 预演

视频演示完，面试官可能追问：

**Q1：你这个 RAG 检索准确率多少？**

> "我用 10 条典型问题做了人工评估，TF-IDF 只能匹配 3 条（关键词命中），Embedding 后 10 条全部语义匹配。最典型的是'心里堵得慌'，TF-IDF 匹配不到'焦虑症'，Embedding 能正确识别。"

**Q2：异步任务失败怎么处理？**

> "RagAsyncTask 失败只记日志，不主动通知前端。后续可以加 RabbitMQ 或者 SSE 通知。但当前 rebuild 是幂等的，下次发布文章会触发重建，自然恢复一致性。"

**Q3：PgVector 和 Milvus 怎么选？**

> "三方面考虑：部署复杂度（Milvus 要 3 个容器，PgVector 一个）、数据一致性（MySQL 和 PostgreSQL 同库通过 chunk_id 关联）、规模（10 万向量以下 HNSW 已经毫秒级返回，没必要上 Milvus）。"
